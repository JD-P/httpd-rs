Reviewed source
---------------

HEAD and origin/main:

The release server was rebuilt before these runs:
  cargo build --release -p httpd-rs

The live harness uses loopback only. It enables the supported access-file
capability, writes one `Require expr` rule under `AllowOverride AuthConfig`,
and sends a 32-byte `X-P42` value that does not match. Every successful
request therefore fails closed with 403.

RLIMIT_AS is used only to turn the otherwise measured resident amplification
into a deterministic allocator failure. The daemon needs unusually large
virtual address headroom for its worker stacks, so 2.7 GiB is not an RSS
claim. The security-relevant measurements are the `/proc` RSS deltas above;
the bounded run confirms the release profile's allocation-failure outcome is
whole-process SIGABRT rather than a fail-closed request error.


Direct wrapper scaling probe
----------------------------

The small Rust probe shares one compiled httpd-rs PCRE2 wrapper across search
threads. With one earlier search already retained, one additional search slot
adds the following RSS as capture count rises (32-byte subject):

  captures  pattern bytes  retained growth from one additional cache
         0             29                                      1,272 KiB
         1             33                                      2,060 KiB
         8             61                                      7,604 KiB
        16             93                                     13,940 KiB
        32            157                                     26,672 KiB
        64            285                                     52,316 KiB
       120            509                                     97,820 KiB

Invocation example:

  P42_CAPTURES=120 P42_SUBJECT_BYTES=32 P42_THREADS=1 \
    P42_ITERATIONS=1 cargo run --release \
    --manifest-path adversarial/p42/regex_pool_probe/Cargo.toml

The wrapper's declared default bounds are 5,718,016 bytes (5.453125 MiB) for
`dependency_workspace_bound()` and 4,456,448 bytes (4.25 MiB) for a match.
The measured 97,820 KiB additional cache is about 22.5 times the match-time
claim before retained-pool multiplicity.
